# 작업 표준 — Next.js 16 App Router

이 문서는 프라임다온 프로젝트 기준입니다. 다른 플랫폼(정적 HTML, 워드프레스, 빌더) 사이트를 다룰 때는 그대로 쓰면 안 됩니다 — 이전 지침서 초판이 정확히 그 실수로 빌드를 깨뜨렸습니다.

**전제 확인**: `app/` 디렉터리가 있으면 App Router. `pages/`면 Pages Router이고 아래 코드는 전부 다릅니다.

---

## 0. 시작 전

### 검색엔진 등록

코드를 아무리 잘 고쳐도 등록이 안 돼 있으면 아무도 못 찾습니다.

| 대상 | 상태 | 비고 |
|---|---|---|
| 구글 서치콘솔 | 등록됨 (도메인 속성) | sitemap 제출 완료 |
| 네이버 서치어드바이저 | **확인 필요** | 국내 B2B는 여기가 더 중요합니다. 사이트맵 제출 + 웹페이지 수집 요청 |
| 네이버 스마트플레이스 | **확인 필요** | 사업장 주소가 있으므로 등록 대상. 회사명 검색 시 지도·정보 노출 여부는 신뢰도 차이가 큽니다 |

### 타입 정의를 먼저 읽는다

`AGENTS.md`가 "이건 네가 아는 그 Next.js가 아니다"라고 경고합니다. 실제로 맞습니다. 메타데이터 API를 손대기 전에 반드시 읽으세요.

```
node_modules/next/dist/lib/metadata/types/metadata-interface.d.ts      # Metadata 전체 필드
node_modules/next/dist/lib/metadata/types/metadata-types.d.ts          # TemplateString
node_modules/next/dist/lib/metadata/types/alternative-urls-types.d.ts  # canonical / languages
```

AI 도구에 시킬 때도 "추측하지 말고 이 파일들을 직접 열어서 확인해줘"를 명시하세요. **이 프로젝트에서 실제로 사고가 났던 지점입니다** — AI가 존재하지 않는 데이터 필드(`p.material`, `p.color`)로 alt를 만들어 빌드가 통째로 깨졌습니다. `|| '기본값'`을 붙여도 소용없습니다. 타입스크립트는 실행 전에 막습니다.

## 1. 메타데이터 (title · description · canonical · hreflang · OG)

### 반드시 알아야 할 병합 규칙

Next.js는 `generateMetadata` 반환값을 상위 레이아웃 metadata와 **최상위 키 단위로 얕게 병합**합니다. 덮어쓰기가 아닙니다.

```ts
// ❌ 이 코드가 지금 사이트의 메타 중복 버그를 만들었습니다
export async function generateMetadata({ params }) {
  const { lng } = await params;
  return { alternates: buildAlternates(lng, "/about") };
}
// alternates만 자기 값. title·description은 레이아웃 값을 그대로 상속.
```

겉보기엔 "이 페이지는 메타데이터를 처리하고 있다"고 읽히기 때문에 리뷰에서 잘 안 걸립니다. **canonical·hreflang은 멀쩡한데 title만 전부 똑같은 사이트를 만나면 거의 확실히 이 원인입니다.**

### `export const metadata`는 언어를 모른다

```ts
// ❌ 정적 평가라 params에 접근할 수 없습니다. lng를 못 봅니다.
export const metadata: Metadata = { title: '...', description: '...' };
```

한 언어로 쓴 문구가 4개 언어 경로 전부에 나갑니다. 라우트 하나만 확인해서는 절대 안 보이고, **서로 다른 언어의 같은 라우트를 비교해야** 드러납니다.

### 올바른 구조

*레이아웃* — 공통 기준값과 접미사 템플릿만.

```ts
// src/app/[lng]/layout.tsx
import type { Metadata } from 'next';
import { getMeta } from '@/lib/meta';   // 32개 조합 사전

export async function generateMetadata(
  { params }: { params: Promise<{ lng: string }> }
): Promise<Metadata> {
  const { lng } = await params;
  const m = getMeta(lng, '/');
  return {
    metadataBase: new URL('https://www.primedaon.com'),
    title: { default: m.title, template: '%s | THE PRIME DAON' },
    description: m.description,
    verification: { other: { 'naver-site-verification': [/* ... */] } },
  };
}
```

`title`이 문자열만 받는 게 아니라는 점이 핵심입니다. 타입 정의에 이렇게 돼 있습니다.

```ts
export type DefaultTemplateString = { default: string; template: string };
```

*각 페이지* — 브랜드명 없는 순수 검색어 title + description + alternates.

```ts
// src/app/[lng]/about/page.tsx
export async function generateMetadata({ params }: { params: Promise<{ lng: string }> }) {
  const { lng } = await params;
  const m = getMeta(lng, '/about');
  return {
    title: m.title,                 // 접미사는 레이아웃 template이 붙임
    description: m.description,
    alternates: buildAlternates(lng, '/about'),
    openGraph: {
      title: m.title,
      description: m.description,
      url: `https://www.primedaon.com/${lng}/about`,
      images: [{ url: `https://www.primedaon.com/og/${lng}.jpg` }],
    },
  };
}
```

**주의 — openGraph도 얕게 병합됩니다.** 페이지에서 `openGraph.title`만 추가하면 레이아웃의 `images`·`siteName`이 통째로 사라집니다. 페이지에서 openGraph를 건드리려면 필요한 필드를 모두 다시 써야 합니다.

### canonical의 함정

- 레이아웃에 `canonical: '/'`만 넣으면 **모든 페이지가 루트를 가리킵니다.** Next.js가 자기 경로로 자동 변환해주지 않습니다.
- `metadataBase`가 있으면 상대 경로를 써도 됩니다.
- hreflang에는 **자기 언어를 포함한 전 언어**가 들어가야 합니다. 상호 참조가 안 맞으면 구글이 세트 전체를 무시합니다.
- `x-default`, 미들웨어 `fallbackLng`, 사이트맵 `exclude`가 서로 어긋나면 안 됩니다.

### 문안 원칙

`[핵심 검색어] [보조 검색어 또는 차별점]` — 브랜드명은 template이 뒤에 붙입니다.

번역이 아니라 **언어별 재작성**입니다. 시장마다 검색어가 다릅니다.

| 언어 | 예시 검색어 |
|---|---|
| 한국어 | 가죽 케이스 OEM 제조, 가죽 소품 공장 |
| 영어 | leather case manufacturer, custom leather goods OEM/ODM |
| 일본어 | 革ケース OEM, レザー小物 製造 (한자어/가타카나 표기가 갈림) |
| 중국어 | 皮革 代工, 皮具 OEM (간체/번체 먼저 결정) |

길이 기준(픽셀 폭 근사): 한/일/중 title 15~32자·description 50~85자, 영어 title 30~60자·description 110~158자.

구체 명사가 형용사를 이깁니다. "압도적인 장인정신"보다 "특수 미싱 11종·레이저 가공·정밀 프레스".

## 2. h1 태그

페이지당 정확히 하나. 없어도 문제고 두 개여도 문제입니다.

App Router는 레이아웃·페이지·여러 컴포넌트가 조합되므로 중복이 생기기 쉽습니다. 배너 컴포넌트에 이미 h1이 있는데 페이지 제목도 h1으로 바꾸면 두 개가 됩니다.

```js
// F12 → Console
document.querySelectorAll("h1").length          // 1이어야 정상
[...document.querySelectorAll("h1")].map(el => el.textContent.trim())
```

CSS로 `display:none` 처리된 숨은 h1도 이 명령은 셉니다.

제목 레벨을 건너뛰지 마세요. h1 → h3은 스크린리더 탐색을 망가뜨립니다. 지금 `ShowroomGallery.tsx:190→209`가 그 상태입니다.

## 3. 이미지

### `next/image`를 쓴다

raw `<img>`를 쓰면 자동 WebP/AVIF 변환과 디바이스별 리사이즈가 전부 우회됩니다. ESLint `@next/next/no-img-element` 위반이기도 합니다.

```tsx
<Image src={p.img} alt={...} fill sizes="(max-width: 768px) 100vw, 280px" className="object-cover" />
```

`fill`을 쓰면 **`sizes`가 필수**입니다. 없으면 `100vw`로 취급되어 2열 그리드에 2배 크기가 전송됩니다. 부모에 `position: relative`가 있어야 합니다.

목록이 길면 상단 몇 장을 빼고 `loading="lazy"`를 지정합니다. `<img>`의 기본값은 `eager`입니다.

### alt 텍스트

눈을 감고 페이지를 듣는 사람에게 사진을 설명하는 문장. 키워드 나열은 스팸으로 감점됩니다.

| 이렇게 쓰지 말고 | 이렇게 |
|---|---|
| 정밀 3D 모델링 CAD 설계 맞춤 제작 방식 | 3D CAD로 가죽 케이스 패턴을 설계하는 화면 |
| 프리미엄 꼼꼼한 봉제 마감 제작 방식 | 숙련공이 가죽 지갑 가장자리를 손으로 박음질하는 모습 |
| (비어 있음) | 브라운 소가죽 카드지갑 OEM 제작 샘플 |

**4개 언어 사이트이므로 alt도 사전 키에서 나와야 합니다.** 한국어 alt를 하드코딩하면 영·일·중 사용자의 스크린리더와 이미지 검색에 그대로 나갑니다.

그리고 68장에 같은 문구를 반복하면 그 자체가 스터핑 신호입니다.

### 템플릿 alt를 만들 때

```tsx
// 먼저 데이터 타입을 직접 열어서 확인할 것
// 실제 존재하는 필드: id, img, category, catName, modelName, productName, title
alt={`${p.productName ?? p.title} ...`}
```

없는 필드를 쓰면 빌드가 통째로 깨집니다. `|| '기본값'`으로는 못 막습니다.

## 4. JSON-LD

Metadata API에 항목이 없어서 유일하게 `<script>`를 직접 씁니다.

**`<head>`를 직접 열면 안 됩니다.** App Router에서 `<head>`를 수동으로 추가하면 metadata 시스템과 충돌해 빌드가 깨지거나 태그가 아예 출력되지 않습니다. `<body>` 안에 넣으세요. 구글은 body에 있어도 읽습니다.

```tsx
<body>
  <script type="application/ld+json"
    dangerouslySetInnerHTML={{ __html: JSON.stringify(orgSchema) }} />
  {children}
</body>
```

`dangerouslySetInnerHTML`인 이유: JSX 안에서 중괄호는 자바스크립트 코드 시작을 뜻합니다. JSON을 그대로 붙여넣으면 객체로 해석하려다 터집니다. 이름은 무섭지만 JSON-LD에는 이게 표준 방식입니다.

현재 `layout.tsx`의 Organization 스키마는 정상 동작 중입니다. 다국어 사이트라면 `description`을 언어별로 바꾸는 것을 검토하세요.

## 5. sitemap.xml · robots.txt

현재 `next-sitemap`(방법 B)을 쓰고 있고 `postbuild`에 연결돼 있어 배포마다 갱신됩니다. 그대로 두면 됩니다.

```json
"scripts": { "build": "next build", "postbuild": "next-sitemap" }
```

**동적 라우트는 자동 수집에서 빠집니다.** 빌드 출력에 `ƒ` 표시가 붙는 라우트입니다. `/contact`가 `searchParams`를 써서 여기 해당하고, B2B에서 문의 페이지는 반드시 색인돼야 하므로 `additionalPaths`로 수동 추가해야 합니다.

`exclude` 배열은 정확히 일치하는 경로만 뺍니다. `exclude: ['/en']`은 영어 홈만 빼고 `/en/about`은 남겨서 언어 하나만 홈이 없는 비대칭 상태를 만듭니다.

**`public/`에 파일을 두면 그대로 서빙됩니다.** 프로토타입 HTML을 여기 두면 구글이 색인합니다. 실제로 그렇게 됐습니다.

## 6. i18n

- 사전 키에 **폴백을 두지 마세요.** `dict.x || "한국어"` 형태는 번역 누락을 조용히 숨깁니다. 폴백을 없애야 누락이 드러납니다.
- 중첩 접근에는 방어를 두세요. `(step.checks ?? []).map(...)`. 키 하나가 없으면 페이지 전체가 백지가 됩니다.
- `dict: any`를 쓰지 마세요. `type Dict = typeof ko`로 파생하면 오타를 빌드가 잡습니다.
- alt·aria-label도 사전에서 나와야 합니다.
- 사업자 정보, 파트너명, 단위(개/대) 같은 것도 전부 대상입니다.

## 7. 본문 분량

B2B 사이트가 1,000자 안팎이면 검색엔진이 무슨 회사인지 판단하지 못합니다. 현재 약 1,200자로 부족합니다.

늘릴 곳은 정해져 있습니다: 제조 역량, 공정 설명, 사례 페이지. "27년 경력" 같은 강한 자산이 한 줄로만 적혀 있으면 아깝습니다. 그 27년에 무슨 일이 있었는지 풀어쓰는 것이 그대로 콘텐츠가 됩니다.

코드 작업이 아니라 콘텐츠 작업이고, 별도 상품으로 팔 수 있는 항목입니다.
