# 관리지침서 — 읽는 순서

프라임다온(primedaon.com) 홈페이지 관리 문서입니다. 이전의 「사이트 정비 작업지시서」(claude.ai 아티팩트)를 대체합니다.

## 이전 문서를 폐기하는 이유

이전 지침서 2판은 절차와 함정 목록은 정확했지만, **01 canonical 절의 예제 코드가 지금 사이트의 메타 중복 버그를 그대로 재생산하는 형태**였습니다. `generateMetadata`가 `alternates`만 반환하면 title·description이 상위 레이아웃에서 상속됩니다. 그 코드를 따라간 결과가 지금 상태입니다.

또한 현황표의 "title·description 양호" 판정이 실제와 반대였습니다. 유일하게 양호로 적힌 칸이 가장 심각한 칸이었습니다.

문서가 틀리면 그 문서를 따르는 모든 작업이 틀립니다. 그래서 새로 씁니다.

## 문서 구성

| 파일 | 내용 | 언제 읽나 |
|---|---|---|
| `01_점검결과.md` | 2026-08-26 전수 점검 결과. 발견된 문제와 그 근거 | 지금 상태를 알아야 할 때 |
| `02_수정목록.md` | 우선순위별 수정 항목. 각 항목의 이유·방법·검증법 | 작업 착수 전. **승인 대상 문서** |
| `03_작업표준.md` | Next.js App Router 기준 표준 작업법 | 코드를 고치기 직전 |
| `04_검증절차.md` | 고쳐졌는지 확인하는 법과 함정 목록 | 작업 후, 배포 전후 |

## 이 문서 체계의 원칙

**모든 판정은 원본 출력을 근거로 한다.** 라이브 HTML, 실제 파일 내용, 실제 타입 정의, 실제 빌드 로그, 실제 콘솔 화면. "적용했습니다"라는 보고는 — 사람의 것이든 AI 도구의 것이든 — 증거가 아닙니다.

`01_점검결과.md`의 모든 항목에는 파일명과 줄 번호, 또는 라이브에서 받아온 실제 값이 붙어 있습니다. 근거 없는 항목은 넣지 않았습니다.

## AI 코딩 도구(안티그라비티)에 작업을 시킬 때

`02_수정목록.md`의 항목을 그대로 붙여넣되, 다음 세 문장을 반드시 함께 넣으세요.

1. "추측하지 말고 타입 정의와 사전(JSON) 구조를 직접 열어서 확인해줘."
2. "수정한 뒤 `npm run build` 출력 원문을 그대로 보여줘."
3. "렌더된 HTML에서 해당 태그가 실제로 어떻게 나오는지 보여줘."

이유는 `04_검증절차.md`의 함정 목록에 있습니다.

## 갱신 규칙

작업할 때마다 `01_점검결과.md`의 상태표를 갱신하세요. 완료 항목은 지우지 말고 **완료 날짜와 근거(빌드 로그·라이브 확인 결과)를 적어 남기세요.** 나중에 "이거 했던가?"를 다시 조사하는 시간이 가장 아깝습니다.
