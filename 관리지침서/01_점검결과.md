## A. 메타데이터 — 심각

### A-1. 전 페이지 title·description 동일

라이브 실측:

```
/ko              <title> THE PRIME DAON | 완벽한 가죽 컬렉션 구현의 새로운 표준
/ko/capabilities <title> THE PRIME DAON | 완벽한 가죽 컬렉션 구현의 새로운 표준   ← 동일
```

**기전.** `src/app/[lng]/layout.tsx:17-19`에 title·description이 정적 `export const metadata`로 하드코딩돼 있습니다. 그런데 8개 라우트(`page`, `about`, `capabilities`, `showroom`, `contact`, `privacy`, `terms`)의 `generateMetadata`가 전부 이 형태입니다.

```ts
// src/app/[lng]/capabilities/page.tsx:4-7
export async function generateMetadata({ params }: { params: Promise<{ lng: string }> }) {
  const { lng } = await params;
  return { alternates: buildAlternates(lng, "/capabilities") };
}
```

Next.js는 `generateMetadata` 반환값을 상위 레이아웃 metadata와 **필드 단위로 병합**합니다. `alternates`만 넣으면 title·description은 레이아웃 값이 그대로 내려옵니다. canonical/hreflang 작업 때 `alternates`만 채우고 끝낸 흔적입니다.

### A-2. 언어별 분기가 아예 없음 — A-1보다 큰 손실

`export const metadata`는 정적 평가라 `params`에 접근할 수 없습니다. 즉 `lng`를 모릅니다. 결과적으로 **`/en`, `/ja`, `/zh` 페이지의 title·description·OG가 전부 한국어로 나갑니다.** `<html lang="en">`인 페이지에 한국어 제목이 붙습니다.

페이지별 중복은 한 언어권에서 순위가 안 오르는 문제지만, 언어 미분기는 해당 언어권 검색에서 색인 가치를 사실상 0으로 만듭니다. 4개 언어를 만든 투자가 3개 언어분 회수되지 않고 있습니다.

OG 이미지도 `thumbnail_ko.jpg` 하나 고정이고 `og:url`은 루트 고정이라 canonical과 불일치합니다.

### A-3. 죽은 SEO 헬퍼

`src/app/[lng]/seo.ts`의 `generatePageMetadata`는 **어디서도 import되지 않습니다**(import 그래프 확인). 실제 사용되는 것은 `src/lib/seo.ts`의 `buildAlternates`. 두 파일은 canonical 생성 방식도 다릅니다(전자 절대 URL, 후자 상대 경로). 죽은 쪽을 고치고 반영이 안 된다며 헤매기 딱 좋은 구조입니다.

### A-4. 기본 언어 신호가 세 방향으로 어긋남

| 위치 | 값 |
|---|---|
| `src/i18n/settings.ts:1` | `fallbackLng = 'en'` — 미들웨어가 미매칭 방문자를 `/en`으로 보냄 |
| `src/lib/seo.ts:6` | `x-default` → `/ko` |
| `next-sitemap.config.js:5` | `exclude: ['/en']` — 영어 홈을 사이트맵에서 제외 |

미들웨어는 영어로 보내고, hreflang은 한국어가 기본이라 하고, 사이트맵은 영어 홈을 숨깁니다. 하나로 통일해야 합니다.

## H. 정상 확인된 것

되짚어 헤매지 않도록 명시합니다. 모두 라이브 또는 코드에서 직접 확인했습니다.

- **canonical** — `/ko` → `https://www.primedaon.com/ko`. non-www로 접근해도 www를 가리킴. 페이지별로 자기 주소. 정상
- **hreflang** — 4개 언어 + `x-default` 출력. 정상 (단 A-4의 기준 불일치는 남음)
- **JSON-LD** — `layout.tsx`의 `<body>` 안에 Organization 스키마 정상 출력
- **sitemap.xml** — `https://www.primedaon.com/sitemap.xml` 23개 URL. 서치콘솔 "발견된 페이지" 23과 일치
- **robots.txt** — www·non-www 양쪽 모두 `Sitemap: https://www.primedaon.com/sitemap.xml`로 정확
- **서치콘솔** — www 사이트맵 2026-08-25 제출, 같은 날 읽힘, 성공. 속성은 도메인 속성(www/non-www 사이트맵이 한 표에 둘 다 성공으로 존재 → URL 접두어 속성이면 불가능)
- **미들웨어 리다이렉트** — 루트 `/` 처리됨, 루프 없음. 307은 Accept-Language 협상이므로 올바른 선택
- **언어 전환** — 현재 경로 보존됨(`/ja/showroom` → `/en/showroom`). 홈으로 튕기지 않음
- **하이드레이션 불일치** — 전 컴포넌트에서 발견되지 않음
- **이펙트 정리** — 등록된 리스너·옵저버의 `removeEventListener`/`disconnect`는 정상

## I. 남은 확인 필요 항목

- `apex(primedaon.com)`가 301 없이 200으로 응답합니다. canonical이 있어 색인 통합은 되지만 301이 정석입니다. Vercel 도메인 설정 확인 필요
- `sitemap.xml`에 `/en` 홈과 `/contact`가 없습니다(원인은 A-4의 `exclude`와 `/contact`의 동적 렌더링)
- `.env.local` 내용은 열지 않았습니다. `ContactForm.tsx`가 읽는 값은 전부 `NEXT_PUBLIC_` 접두어(EmailJS service/template/public key)로, 공개돼도 되는 값들입니다. 다만 `.gitignore`에 `.env*`가 있는지 확인했고 있습니다 — 정상
